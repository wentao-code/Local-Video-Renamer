# 持久化任务暂停与恢复设计

## 目标

为任务列表增加暂停和继续能力。暂停采用协作式语义：当前正在执行的单个视频、一次模型调用或一次 FFmpeg 调用完成后，任务进入暂停状态；不强制冻结或杀死外部进程。应用重启后，仍可从任务列表恢复具备恢复描述的任务。

## 现状与边界

现有 `GuiTaskQueue` 负责 FIFO 调度，任务记录和回调主要保存在内存中，已有 `pause_requested` 和 `TASK_STATUS_PAUSED` 基础字段。回调是 Python 闭包，无法直接序列化，因此不能把所有临时 GUI 操作都伪装成可恢复任务。

本设计将任务分为两类：

- 可恢复任务：入队时提供稳定的 `resume_kind` 和 JSON `resume_payload`，应用重启后可由注册表重新构造回调。字幕按编号任务、补全计划任务属于首批支持对象。
- 当前会话任务：没有恢复描述的查看、临时刷新等任务仍可暂停当前队列，但重启后标记为“不可恢复”，不自动执行。

## 数据模型

在应用主 SQLite 数据库中新增 `gui_task_records` 表，作为任务生命周期的持久化日志和恢复来源。建议字段：

- `task_id`：本地任务编号，主键。
- `trace_task_id`：跨模块日志追踪 ID。
- `title`、`source`、`task_category`、`task_kind`、`plan_id`、`plan_task_kind`。
- `status`：等待、执行、暂停、取消中、完成、部分完成、已删除、不可恢复。
- `resume_kind`、`resume_payload_json`、`resumable`：恢复任务类型和参数。
- `attempts`、`max_attempts`、`pause_reason`、`last_error`、`last_run_id`、`last_run_result_json`。
- `created_at`、`started_at`、`paused_at`、`completed_at`、`updated_at`。

队列仍保留内存对象，以便 Qt 调度；每次状态变化通过一个持久化适配器同步 SQLite。应用启动时读取 `waiting`、`running`、`paused` 状态：`running` 统一转为 `paused` 并记录“应用上次退出时中断”，有恢复描述的任务重新注册到队列，其他任务显示为不可恢复。

## 状态流转

```text
等待中 -> 正在执行 -> 已完成/部分完成
             |
             +-> 请求暂停 -> 当前工作单元完成 -> 已暂停
             |
             +-> 请求删除 -> 取消中 -> 已删除

已暂停 -> 点击继续 -> 等待中 -> 正在执行
```

点击暂停时：

1. 队列将当前记录标记为 `pause_requested`，停止启动后续等待任务。
2. 当前任务在安全边界返回后，队列将其放回等待列表并持久化为 `paused`。
3. 继续操作清除暂停原因和请求标志，恢复为 `waiting`，随后按 FIFO 执行。

点击继续时不重复执行已经完成的工作。字幕任务的恢复参数包含输入目录、视频编号和候选运行 ID；字幕生成服务已有外部字幕、内嵌字幕和生成记录检查，因此重启后会重新校验并从该编号当前未完成阶段继续。

## 任务列表界面

新增“暂停/继续”操作按钮：

- 选中正在执行或等待中的可暂停任务时显示“暂停”。
- 选中已暂停或不可恢复任务时显示“继续”或禁用并显示原因。
- 正在执行的任务暂停请求发出后按钮显示“暂停中”，避免重复点击。
- 暂停原因和不可恢复原因继续显示在“暂停原因”列。

任务列表刷新时从队列快照读取状态；启动恢复完成后再次刷新，用户可以看到实际恢复结果。

## 恢复注册表

新增 `TaskResumeRegistry`，按 `resume_kind` 注册恢复工厂，例如：

- `subtitle_pipeline_video`：调用现有按视频编号的字幕生成与 FFmpeg 封装管线。
- `enrichment_plan`：调用现有补全计划恢复逻辑，复用计划表和计划明细。

未知 `resume_kind`、损坏的 JSON、输入视频已不存在或恢复工厂失败时，任务改为“不可恢复”，保留错误信息，不自动启动其他任务。

## 错误处理与一致性

任务状态更新使用 SQLite 事务；队列先更新内存状态，再由适配器写库失败时记录错误并恢复原状态。恢复加载采用幂等规则，以 `task_id` 和 `resume_payload` 防止重复创建任务。删除任务保留数据库记录，不删除执行历史。

## 测试范围

- 队列：暂停请求在当前回调完成后进入暂停，继续后按 FIFO 恢复；等待任务可直接暂停；暂停任务不会被启动。
- 持久化：状态变化写入 SQLite；重启模拟会把运行中任务转为暂停；恢复任务只注册一次。
- 恢复：字幕任务能按编号重建；完成字幕/封装的编号不会重复处理；未知任务类型转为不可恢复。
- UI：任务列表按钮随状态切换；不可恢复任务不会误显示继续可用。
- 回归：现有取消、重试、查看模式暂停、补全计划恢复和字幕流水线测试继续通过。

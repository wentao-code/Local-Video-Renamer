# 本地视频字幕生成接入设计

## 目标

在不修改 `D:\software\software_for_chickenrice` 模型发行目录、不修改现有批处理文件、不调用 ffmpeg 的前提下，将模型字幕生成能力接入 VidNorm 主界面。

## 方案

字幕功能使用固定输入目录 `user_data/translation_videos`，后台递归发现其中的真实视频路径，并通过 `infer.exe` 子进程生成字幕。该目录可通过 `TRANSLATION_INPUT_DIR` 修改。调用进程的工作目录固定为模型根目录，以满足模型程序对 `models`、VAD 文件和 `generation_config.json5` 的相对路径要求。

不模拟拖拽批处理文件，因为批处理末尾的 `pause` 会阻塞后台任务。系统直接使用与 GPU 视频批处理一致的参数：视频扩展名、`srt,vtt,lrc` 输出格式和 `cuda` 设备。

## 数据流

```text
固定字幕目录 -> 后台递归发现视频 -> 生成字幕任务 -> 调用 infer.exe -> 检查字幕文件 -> 返回逐文件结果
```

当前阶段不写入数据库、不执行 ffmpeg 封装。模型先在视频原目录生成字幕，生成成功后系统使用现有番号解析规则提取完整视频编号（例如从 `RCTD-116 sample title.mp4` 提取 `RCTD-116`）创建子目录，并将视频和字幕一起移动进去。字幕文件保留原文件名，模型自身负责跳过已有字幕；系统通过 `--overwrite` 配置控制覆盖行为。归档不会覆盖目标目录中的同名文件。

字幕流程写入独立的 `runtime/logs/translation.log`，每次任务生成 `run_id`，并沿用 HTTP 请求的 `correlation_id`。日志包含目录扫描、模型命令和工作目录、进程退出码、耗时、stdout/stderr 摘要、字幕缺失、归档结果和最终汇总；接口结果同时返回 `run_id` 便于定位。

为兼容模型对 Windows 文件名和控制台编码的限制，模型执行前会把包含标题或特殊字符的视频临时改为完整番号文件名，并将原始路径写入临时 JSON 映射。模型结束后，无论成功或失败，系统都会按映射恢复原视频名，再将视频和字幕归档到番号目录；临时映射文件随后删除。

## 失败与验证

- 模型目录或 `infer.exe` 不存在时立即返回参数错误；固定输入目录不存在时自动创建。
- 固定输入目录没有支持的视频时返回零条结果，不启动模型进程。
- 模型进程非零退出时任务失败，并保留模型输出日志。
- 模型进程退出码为零但未生成目标字幕时任务失败，避免误报成功。
- 单个文件失败不影响同批其他文件，接口返回逐文件状态和汇总数量。
- 归档目标已存在同名文件时，该视频归档失败，不覆盖现有文件。

## 配置

通过 `.env` 支持以下配置，并为当前模型目录提供默认值：

- `TRANSLATION_MODEL_ROOT`
- `TRANSLATION_INFER_EXE`
- `TRANSLATION_DEVICE`
- `TRANSLATION_SUB_FORMATS`
- `TRANSLATION_OVERWRITE`
- `TRANSLATION_INPUT_DIR`

## 界面

主界面的“生成字幕”操作独立于本地视频扫描，点击后处理固定字幕目录。操作进入现有 GUI 任务队列，完成后提示目录、成功数量和失败数量；调用期间不阻塞界面。
